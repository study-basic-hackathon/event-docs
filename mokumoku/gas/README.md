# もくもく会バナー ジェネレーター（GAS版）

`mokumoku/generator.html` を Google Apps Script (GAS) の Web アプリとして
ホスティングするためのプロジェクトです。会社のGoogle Workspaceは使っていない
前提なので、アクセス制御は **サーバー側（`Code.gs`）での合言葉チェック** で
行います。

## なぜサーバー側でチェックするのか

最初はクライアント側（JS）だけでパスワードをチェックする案でしたが、それだと
「パスワードが合っているかどうかに関係なく、生成ツール本体（HTML/JS一式）は
常にブラウザへ送られてしまい、見た目だけ隠す」形になり、DevToolsで一行打てば
中身に到達できてしまいます。そこで **`doGet`/`doPost` の時点でパスワードを
検証し、合っている場合だけ `index.html`（本体）を返す** ように変更しました。
間違っている・未入力の場合はログインフォームだけが返るので、本体のコードは
そもそもブラウザに届きません。

- `ANYONE_ANONYMOUS` — リンクを知っていればGoogleアカウントなしでも
  ログインフォームまでは辿り着けます（＝実際の関所はサーバー側のパスワード）

## 中身

- `Code.gs` — `doGet`/`doPost` でパスワードを検証し、正しければ `index.html` を、
  間違っていればログインフォームを返す
- `index.html` — `mokumoku/generator.html` と同じもの（パスワードゲートなし。
  ここまで来られた時点で認証済みのため）
- `appsscript.json` — マニフェスト。`webapp.access` は `ANYONE_ANONYMOUS`

## デプロイ手順

**⚠️ 前提として: `clasp deploy` 単体では正しくWebアプリになりません。**
`appsscript.json` の `webapp` 設定（`access`/`executeAs`）を、`clasp deploy` は
Apps Script APIへのリクエストに含めないという既知の不具合があります
（[google/clasp#1115](https://github.com/google/clasp/issues/1115)）。そのため
`clasp deploy` だけで作ったデプロイは「Webアプリのエントリーポイントが
設定されていないデプロイ」になり、URLを開いても本体が動かず、バージョンの
自動ドキュメント（"Library Documentation"というページ）しか表示されません。

そのため **初回デプロイだけは script.google.com のUIで手動、種類を明示的に
「ウェブアプリ」に指定して行う** 必要があります。2回目以降はそのデプロイに
対して `clasp deploy -i <デプロイID>` でバージョンだけ更新すればOKです
（既存のWebアプリ設定はそのまま保持されます）。

### コード同期は clasp、初回デプロイは手動（推奨フロー）

```bash
npm install -g @google/clasp
clasp login
cd mokumoku/gas
clasp create --type webapp --title "もくもく会バナー ジェネレーター"
clasp push
```

ここまでで `.clasp.json` が生成されます（scriptId が入るのでコミット不要、
リポジトリの `.gitignore` に追加済みです）。続いて:

```bash
clasp open
```

でエディタを開き、右上「デプロイ」→「新しいデプロイ」→ 種類の選択（歯車
アイコン）で **「ウェブアプリ」** を明示的に選択 → アクセスできるユーザーを
「全員」にしてデプロイしてください。ここで発行されたデプロイIDを

```bash
clasp deployments
```

で確認しておきます（`- AKfycby...xxxx @1` のような形式）。

**2回目以降の更新**は、このIDを指定して:

```bash
clasp push
clasp deploy -i <上で確認したデプロイID>
```

`-i` を付け忘れると新しいデプロイ（＝新しいURL）が作られてしまうので
必ず指定してください。URLを確認したいときは `clasp open --webapp` で
ブラウザから直接開けます。

### 完全に手動で行う場合

1. https://script.google.com/ で新規プロジェクト作成
2. デフォルトの `Code.gs` の中身をこのフォルダの `Code.gs` で置き換え
3. ファイル追加 → HTML → ファイル名を `index`（拡張子なし）にして
   このフォルダの `index.html` の中身を貼り付け（1.3MBあるので少し重いです）
4. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」→ アクセスできる
   ユーザーは「全員」

## パスワードの設定 ★デプロイ前に必ずやること

1. `Code.gs` の一番下、`setPassword()` 関数の中の

   ```js
   var newPassword = 'change-me-please'; // ここを書き換えてから実行する
   ```

   を実際に使いたいパスワードに書き換える
2. Apps Scriptエディタの関数選択プルダウンで `setPassword` を選び、▶実行
   （初回は権限の承認を求められるので許可してください）
3. 実行ログに「パスワードを設定しました。」と出れば完了。パスワードは
   `PropertiesService`（スクリプトのプロパティ）に保存されるので、`Code.gs`
   に書いた行は元の `'change-me-please'` に戻しておくと安心です（サーバー側の
   保存値には影響しません）
4. すでにデプロイ済みなら再デプロイは不要です（`setPassword()`の実行だけで
   即座に反映されます）。まだデプロイしていない場合は上記「デプロイ手順」の
   通りにデプロイしてください

パスワードを変更したいときは、同じ手順で `setPassword()` を書き換えて
再実行するだけです（再デプロイ不要、実行した瞬間から新しいパスワードになります）。

## URLとパスワードの共有

`clasp deploy` 後（または手動デプロイ後）に表示される「ウェブアプリのURL」と、
上で設定したパスワードをメンバーに共有してください。フォームは `method="post"`
で送信するので、パスワードがブラウザの履歴やURLに残ることはありません。

ページを再読み込みするたびにパスワード入力が必要になります（サーバー側で
毎回検証する設計のため、ログイン状態を保持する仕組みは持たせていません）。
毎回開くたびに入力してもらう運用で問題なければこのままで、頻繁に使うなら
チームのパスワードマネージャー等に登録しておくのがおすすめです。

### トラブルシューティング: 「Library Documentation」というページが出る

URLを開いたときに、`doGet`/`doPost`/`setPassword`が引数一覧として並んだ
「Library Documentation」というページが表示される場合は、`clasp deploy`
だけでWebアプリの種類指定をせずにデプロイしてしまっているのが原因です
（[上記「デプロイ手順」の注意書き](#デプロイ手順)を参照）。UIで種類を
「ウェブアプリ」に指定して手動デプロイし直してください。

## 既知の注意点：ダウンロードボタン

GAS の Web アプリはコンテンツを sandbox 付き iframe の中で配信します。
環境によっては `<a download>` によるファイル保存ボタンがブロックされる
可能性があるため、`index.html` 側でダウンロード実行後に「保存できない場合は
こちら（新しいタブで開く）」という予備ボタンが出るようにしてあります。
そちらを押すと画像が新しいタブで開くので、右クリック→「名前を付けて画像を保存」
で保存できます。

## 更新のしかた

1. ローカルの `mokumoku/generator.html` を直したら、それを
   `mokumoku/gas/index.html` にもコピー
2. `clasp push` のあと、**同じURLを保つために** `clasp deploy -i <既存のデプロイID>`
   を実行（IDは `clasp deployments` で確認。`-i` を忘れて素の `clasp deploy` を
   実行すると新しいURLのデプロイが増えてしまいます）
   - 手動の場合は「デプロイを管理」→ 既存デプロイの鉛筆アイコン（編集）→
     「新バージョン」を選んで「デプロイ」（＝「新しいデプロイ」ボタンは使わない）
