# イベントバナー ジェネレーター（GAS版）

`banner-generator/generator.html` を Google Apps Script (GAS) の Web アプリとして
ホスティングするためのプロジェクトです。会社のGoogle Workspaceは使っていない
前提なので、アクセス制御は **サーバー側（`Code.gs`）での合言葉チェック** で
行います。

> **旧 `mokumoku/gas/` からの移行です。** 以前はもくもく会専用でしたが、
> タイトル・日付を自由に編集できる汎用ジェネレーターに拡張したのに合わせて
> この場所に引っ越しました。旧フォルダは削除済みです。**Apps Scriptプロジェクト
> 自体は作り直さず、既存プロジェクト（`.clasp.json`のscriptIdが指している方。
> `.clasp.json`はgit管理外なのでこのフォルダにコピー済みです）にこの新しい
> コードを上書きデプロイします。** そのため既存のURL・既存のパスワードは
> そのまま変わりません。メンバーへの再共有は不要です。

## なぜサーバー側でチェックするのか

最初はクライアント側（JS）だけでパスワードをチェックする案でしたが、それだと
「パスワードが合っているかどうかに関係なく、生成ツール本体（HTML/JS一式）は
常にブラウザへ送られてしまい、見た目だけ隠す」形になり、DevToolsで一行打てば
中身に到達できてしまいます。そこで **`doGet`/`doPost` の時点でパスワードを
検証し、合っている場合だけ `index.html`（本体）を返す** ように変更しました。
間違っている・未入力の場合はログインフォームだけが返るので、本体のコードは
そもそもブラウザに届きません。

- `ANYONE_ANONYMOUS` — リンクを知っていればGoogleアカウントなしでも
  ログインフォームまでは辿り着けます（＝実際の関所はサーバー側のパスワード）

## 中身

- `Code.gs` — `doGet`/`doPost` でパスワードを検証し、正しければ `index.html` を、
  間違っていればログインフォームを返す
- `index.html` — `banner-generator/generator.html` と同じもの（パスワードゲート
  なし。ここまで来られた時点で認証済みのため）
- `appsscript.json` — マニフェスト。`webapp.access` は `ANYONE_ANONYMOUS`

## デプロイ手順（既存プロジェクトへの反映）

このフォルダの `.clasp.json` は、もくもく会バナー専用だった頃からすでに
動いている既存のApps Scriptプロジェクトを指しています。**新規プロジェクトを
作る必要はありません。** コードを同期して、同じデプロイにバージョンを
追加するだけです。

```bash
npm install -g @google/clasp   # 未インストールの場合のみ
clasp login                    # 未ログインの場合のみ
cd banner-generator/gas
clasp push
```

次に、更新対象の既存デプロイIDを確認します（前回すでに手動で「ウェブアプリ」
として正しく設定済みのはずのデプロイです）。

```bash
clasp deployments
```

一覧に出てくるデプロイID（`- AKfycby...xxxx @N` のような形式）を使って:

```bash
clasp deploy -i <上で確認したデプロイID>
```

これで同じURL・同じパスワード設定のまま、中身だけ新しいジェネレーターに
更新されます。URLを確認したいときは `clasp open --webapp` でブラウザから
直接開けます。

**⚠️ `-i` を省略しないこと。** `clasp deploy` を `-i` なしで実行すると、
既存デプロイを更新するのではなく**新しいデプロイ（＝新しいURL）**が
作られてしまいます。また、そもそも`-i`なしの新規デプロイでは
`appsscript.json`の`webapp`設定（`access`/`executeAs`）がAPIリクエストに
含まれないclasp側の既知の不具合もあります
（[google/clasp#1115](https://github.com/google/clasp/issues/1115)）。
実際、旧`mokumoku/gas/`で `clasp pull` した際に `appsscript.json` の
`webapp`ブロックが消えて`timeZone`まで書き換わっていたことがあり、この
不具合の裏付けになっています。

### 参考: まったく新しいプロジェクトとして作り直したい場合

（通常は不要です）別のURL・別のパスワード設定で完全に切り離したい事情が
あれば、`.clasp.json`を削除してから`clasp create --type webapp --title "..."`
を実行し、新規プロジェクトとして作成できます。その場合は初回デプロイだけ
script.google.com のUIで手動、種類を明示的に「ウェブアプリ」に指定して行う
必要があります（理由は上記の不具合と同じです）。

### 完全に手動で行う場合（clasp を使わない場合）

1. https://script.google.com/ で**既存のプロジェクトを開く**（`.clasp.json`の
   scriptIdと同じプロジェクト。新規作成しないこと）
2. `Code.gs` の中身をこのフォルダの `Code.gs` で置き換え
3. `index` という名前のHTMLファイルの中身を、このフォルダの `index.html` で
   置き換え（1.3MBあるので少し重いです）
4. 「デプロイ」→「デプロイを管理」→ 既存デプロイの鉛筆アイコン（編集）→
   「新バージョン」を選んで「デプロイ」（＝「新しいデプロイ」ボタンは
   使わない。使うと新しいURLが発行されてしまいます）

## パスワードの設定

既存プロジェクトを再利用する今回のケースでは、**すでに設定済みのパスワードが
そのまま使えるので、この節の作業は不要です。** パスワードを変更したい場合や、
まったく新しいプロジェクトとして作り直した場合のみ以下を行ってください。

1. `Code.gs` の一番下、`setPassword()` 関数の中の

   ```js
   var newPassword = 'change-me-please'; // ここを書き換えてから実行する
   ```

   を実際に使いたいパスワードに書き換える
2. Apps Scriptエディタの関数選択プルダウンで `setPassword` を選び、▶実行
   （初回は権限の承認を求められるので許可してください）
3. 実行ログに「パスワードを設定しました。」と出れば完了。パスワードは
   `PropertiesService`（スクリプトのプロパティ）に保存されるので、`Code.gs`
   に書いた行は元の `'change-me-please'` に戻しておくと安心です（サーバー側の
   保存値には影響しません）
4. すでにデプロイ済みなら再デプロイは不要です（`setPassword()`の実行だけで
   即座に反映されます）。まだデプロイしていない場合は上記「デプロイ手順」の
   通りにデプロイしてください

パスワードを変更したいときは、同じ手順で `setPassword()` を書き換えて
再実行するだけです（再デプロイ不要、実行した瞬間から新しいパスワードになります）。

## URLとパスワードの共有

既存プロジェクトを再利用する今回のケースでは、URL・パスワードとも既存のまま
なので**改めて共有し直す必要はありません。** まったく新しいプロジェクトとして
作り直した場合のみ、新しい「ウェブアプリのURL」と新しく設定したパスワードを
メンバーに共有してください（フォームは `method="post"` で送信するので、
パスワードがブラウザの履歴やURLに残ることはありません）。

ページを再読み込みするたびにパスワード入力が必要になります（サーバー側で
毎回検証する設計のため、ログイン状態を保持する仕組みは持たせていません）。
毎回開くたびに入力してもらう運用で問題なければこのままで、頻繁に使うなら
チームのパスワードマネージャー等に登録しておくのがおすすめです。

### トラブルシューティング: 「Library Documentation」というページが出る

URLを開いたときに、`doGet`/`doPost`/`setPassword`が引数一覧として並んだ
「Library Documentation」というページが表示される場合は、`clasp deploy`
だけでWebアプリの種類指定をせずにデプロイしてしまっているのが原因です
（上記「デプロイ手順」の注意書きを参照）。UIで種類を
「ウェブアプリ」に指定して手動デプロイし直してください。

## 既知の注意点：ダウンロードボタン

GAS の Web アプリはコンテンツを sandbox 付き iframe の中で配信します。
環境によっては `<a download>` によるファイル保存ボタンがブロックされる
可能性があるため、`index.html` 側でダウンロード実行後に「保存できない場合は
こちら（新しいタブで開く）」という予備ボタンが出るようにしてあります。
そちらを押すと画像が新しいタブで開くので、右クリック→「名前を付けて画像を保存」
で保存できます。

## プリセット（タブ）について

もくもく会・ハッカソン・自由入力（テンプレなし）の3タブは `generator.html`
内の `buildPresets()` にハードコードされています。チーム全員で共有する保存機能
までは持たせていません（都度「自由入力」タブから作って構わないという判断のため）。
新しい固定タブを増やしたい場合は `buildPresets()` にオブジェクトを1つ追加して
`<div class="tabs">` にボタンを1つ追加してください。

## 更新のしかた

1. ローカルの `banner-generator/generator.html` を直したら、それを
   `banner-generator/gas/index.html` にもコピー
2. `clasp push` のあと、**同じURLを保つために** `clasp deploy -i <既存のデプロイID>`
   を実行（IDは `clasp deployments` で確認。`-i` を忘れて素の `clasp deploy` を
   実行すると新しいURLのデプロイが増えてしまいます）
   - 手動の場合は「デプロイを管理」→ 既存デプロイの鉛筆アイコン（編集）→
     「新バージョン」を選んで「デプロイ」（＝「新しいデプロイ」ボタンは使わない）
